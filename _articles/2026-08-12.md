## The decisions

### Generation-over-content: deck items synthesized fresh from the official guide, never transcribed — *model-behavior-as-design*

Every CCAR-F hard-mode item was generated by authoring from first principles against the official guide's task-statement bullets, then blind-solve validated — not transcribed from existing practice banks. Blind-solve validation means every item was solved by the author before the answer was reviewed; no item shipped without a verified solution path. This means the deck ages with the exam spec, not with a stale third-party corpus. The distinction matters: a transcribed deck inherits the errors and gaps of its source; a generated deck inherits only the official task-statement structure.

Tags: `generation-over-content`, `cca-prep`

### Hashed privacy name gate: the gate must cover its own merge artifacts — *security-as-emergent-ux*

PR #10 added a privacy gate that hashes operator names in research deposits. PR #11 immediately revealed the gate's own boundary condition: two parallel-session deposits landed on main after the branch point, meaning the gate's merge ref contained unredacted names it was supposed to sanitize. The fix — boundary-check skips symlinks, which CI has no targets for — addresses the specific artifact class that caused the failure: symlinked index files that CI does not traverse and that therefore escaped the initial gate sweep. The corrected gate runs a post-merge check on the merge commit itself in addition to the branch-time sweep, catching deposits that arrive on main after the branch was cut. The architectural lesson is about enforcement boundary placement: a gate that runs only at branch time cannot sanitize artifacts that arrive on the target branch after the branch was cut. Policy enforcement that touches artifacts must account for the full artifact timeline, not just the branch-time snapshot.

### Three-tier source policy: provenance rules for deck content — *model-behavior-as-design*

PRs #4–#5 committed the three-tier source policy for cca-prep deck content. Tier 1 is the official exam guide (Cisco-published task-statement bullets) — the only authoritative source for item scope. Tier 2 is first-principles synthesis by the author — generation against Tier 1, never transcription. Tier 3 is third-party practice banks — permitted only as negative examples (to verify coverage gaps), never as item sources. The policy exists because mixing source tiers silently degrades deck quality: Tier 3 items often reflect outdated exam versions or contain errors, and they are undetectable once transcribed into the deck. The three-tier rule makes source provenance explicit and enforceable at review time.
