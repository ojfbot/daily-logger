### Instrument surface: why mock decks must be walled from the drill pool — *model-behavior-as-design*

cca-prep is a self-authored exam preparation system for two tracks: CCAR-F (CCA Ranger) and CCDV-F (CCA Data Vault). Every deck is one of four types: H-series (hard drills), E-series (edge cases), X-series (bridge/cross-domain), or M-series (mock instruments). The M-series distinction is architectural: a mock instrument is a blind-solve exam simulation, not a drill resource. PRs #16 and #25 together establish the instrument-surface boundary. The `surface` field lives in each deck's metadata registration inside `exam.json` — the single source of truth for what decks exist and what role they play. Decks registered with `surface: "instrument"` are excluded at every drill-bank access point in `src/`. Without this guard, a 60-question mock deck (M1, M2) enters the STRETCH or HARD drill pool the moment any bridge deck lands — burning the instrument's blind-solve value before the operator ever sits it. The three bugs found live during the M2 sitting (#25) shared one root: code paths that read deck items without first checking the `surface` field. The observable symptom in each case was mock items appearing as candidates in the active drill pool. The fix is a guard at every drill-bank access point, not a patch on the mock deck itself. What the retrospective revealed is that no grep audit was run before #25 merged — meaning the live sitting was the de facto QA environment for this boundary. That is the process failure worth naming. The acceptance condition for the surface boundary is not 'three paths fixed' — it is 'every access point in `src/` that reads deck items confirms the surface field before proceeding.' That condition was not verified at merge. It must be verified before the next sitting.

### Generation-over-content: why cca-prep authors fresh questions rather than recycling official ones — *model-behavior-as-design*

Every deck in cca-prep (H-series, E-series, X-series, M-series, DV-series) is authored fresh-context from the official exam guide task statements — not lifted from existing practice resources. This is the generation-over-content thesis: a QA-gated fresh question tests recall and reasoning simultaneously, while a recycled question tests whether you've seen the source material. The quality gate is blind-solve validation: the author drafts an item, then solves it cold before committing. If blind-solve fails, the item is rejected — not adjusted until it passes. This is the rejection criterion, not a retry loop. The same discipline applies to the M-series mock instruments: M1 and M2 are full-parity blind instruments, meaning the author has not seen the solution set at sitting time. The gate is only honest if the author holds that boundary.
