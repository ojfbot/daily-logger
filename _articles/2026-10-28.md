## The decisions

### Pack generated coverage as reversible tuple rows when the dated-file cap is exceeded — *tooling-for-iteration*

Before PR #483, exceeding the 64 KiB dated-file limit caused the workflow to abort with no receipt saved — the failure mode that halted the October 26 acceptance run at 03:13Z. The fix introduces a fallback that serialises only the generated coverage report as reversible tuple rows when the complete file would overflow. Primary citations, action identities, decisions, and history remain in their original form; the coverage section is replaced by a compact tuple sequence that can be replayed to reconstruct the original coverage JSON. The 64 KiB limit itself is unchanged — PR #483 manages around it, not through it. Issue #386 is the open item that addresses the limit and the budget semantics upstream.

Tags: `editorial-pipeline`, `ci-cd`, `hardening`

### Derive hidden-row evidence requests from the same normalised article status as selection and validation — *security-as-emergent-ux*

The October 26 acceptance stalled because the hidden-row evidence request builder read from a stale, empty snapshot of action keys while the validator used the two live action obligations. Their case digests differed, so the workflow aborted before recording any article. This was a design gap, not a race condition: two subsystems had been wired to different sources of truth for the article's action state. PR #480 made both paths read from the same normalised article status and authoritative actionEvidenceScope — the module that holds the resolved, per-article scope of evidence obligations. The source and changed-key rejection gates were not relaxed; only the input snapshot was unified.

Tags: `editorial-pipeline`, `model-behavior-as-design`

### Grant the accepted article a one-use revision cycle rather than a generation cycle when a pending revision exists — *model-behavior-as-design*

After acceptance, the post-acceptance route previously admitted only generation grants; a pending revision ID would be rejected before reaching the model. PR #484 maps the correct effective cycle type — a pending revision gets a new revision ID equal to the one-use operation UUID — so the article's actual editorial state drives the dispatch path, not a hardcoded generation assumption. The one-use grant registered for October 26 is consumed regardless of run outcome; a fresh grant is required for any follow-up.

Tags: `editorial-pipeline`, `assistant-centric`

### Factor repeated generated metadata in the model view without discarding authored evidence — *tooling-for-iteration*

PR #416's collected source was 250,399 bytes, above the 128 KiB source limit, because repeated coverage metadata dominated the aggregate payload. PR #470 allowed the collector to factor that metadata in the model view while keeping raw source IDs, hashes, and authored lines intact and citable. Factored metadata is marked non-citable; original authored and API lines retain their citation endpoints. This is a view-layer transformation — the underlying evidence is unchanged.

Tags: `editorial-pipeline`, `ci-cd`

### Record bounded rule, stage, and attempt diagnostics on candidate validation failures — *tooling-for-iteration*

Before PR #472, a candidate validation failure could leave only a broad structured-output receipt, hiding which native rule failed and at what stage. The fix records a bounded rule identifier, the stage name, and whether the attempt was initial or a repair — retaining only validated current candidate IDs and bounded counts. Old actual receipts remain readable; the fix does not invent diagnostics for past failures.
