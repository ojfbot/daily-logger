## The decisions

### Derive the sweep set from `gh repo list` at runtime, never from a hardcoded list — *tooling-for-iteration*

The silent-sweep bug had two independent causes: `--paginate` overflowed `execSync`'s synchronous buffer (large org listings silently truncated), and the collector was building its repo set from a committed static list that had drifted 35 days behind the live fleet. The fix replaces `execSync` with a streamed `spawnSync` call piped through stdout, and derives the sweep set dynamically via `gh repo list` at runtime. A hardcoded list means every new repo registration requires a matching collector update — which is exactly the kind of invisible coupling that produces 35 consecutive silent no-ops before anyone notices. The blast radius of the 35-day gap: the four repos that registered during that window (jim-camera, play-well cluster, dealdesk, foundry-recipes) were not swept. Their state changes during that window were not captured in the daily blog. PR #280 backport-registers them; the data gap is acknowledged but the missing daily entries are not retroactively reconstructable.

Tags: `ci-cd`, `daily-logger`, `cleanup`

### Private repos require explicit `REPO_NOTES` opt-in before the sweep touches them — *security-as-emergent-ux*

As part of the same RCA, private repos were excluded from the public sweep unless they opt in via `REPO_NOTES`. This is a security-as-emergent-UX decision: the collector running against org-visible repos should not implicitly surface private repo state in a publicly-readable blog. The opt-in gate makes the boundary explicit and auditable — a new private repo cannot accidentally appear in the public sweep output without a deliberate registration act.

Tags: `security-scanning`, `daily-logger`, `ci-cd`

### Self-reports must be reconciled against shipped code before a roadmap is registered — *model-behavior-as-design*

cv-builder's docs claimed the V2 API was the default and that Phase 2 agents were 'Ready to Start' — both were false relative to the code at `main @ b670930`. PR #155 made the reconciliation a prerequisite for registering `rm-l1-cv-builder` in the northstar. A roadmap registered against a false self-report turns the northstar into a vanity metric: slices will show as completed even when the underlying functionality never ran. This is now standing policy: reconciliation gates registration, not the reverse.

Tags: `cv-builder`, `adr`, `assistant-centric`

### The register-lint CI check must fire on every PR, not only when the register file is touched — *tooling-for-iteration*

lego-village-pipeline's `register-lint.yml` had a `paths:` filter that skipped the check on PRs not touching the register. Since `register-lint` is a required status check with `enforce_admins: true`, this silently allowed PRs to pass a gate that never ran. The fix removes the `paths:` filter from `.github/workflows/register-lint.yml` entirely, so every PR receives the lint signal. A required check that selectively skips is worse than no check — it creates false confidence that the gate is protecting the invariant. If the lint run cost becomes a concern, the correct response is to speed up the lint, not re-introduce a path filter that defeats the required-check guarantee.

Tags: `ci-cd`, `lego-village-pipeline`, `hardening`

### The test battery must tolerate forward register state before the first canary lands — *tooling-for-iteration*

The initial test suite for the lego-village-pipeline register was pinned to the exact state left by the 032 migration — a fixed snapshot, not a structural invariant. The first real correspondence landing (CORR-LEGO-PIPE-036-R0) turned 10 tests red because the suite expected a specific frozen shape rather than asserting that the shape was valid. PR #29 fixed this before the canary merged, establishing the principle: tests should assert structural invariants, not frozen snapshots, when the register is designed to grow.

Tags: `lego-village-pipeline`, `ci-cd`, `hardening`

### Fleet onboarding is a multi-surface ceremony, not a single-file registration — *assistant-centric*

Backporting four repos (jim-camera, play-well cluster, dealdesk, foundry-recipes) required coordinated PRs across daily-logger, morning-cockpit, and core — each with their own surfaces: sweep collection, REPO_META, northstar registry, roadmap registry, and the CLAUDE.md ecosystem table. The ceremony is intentionally redundant: each surface serves a different consumer (the blog sweep, the cockpit fleet card view, the northstar roadmap renderer) and drift between them is the failure mode the RCA exposed. What this architecture does not yet have is a reconciliation check — a lint or CI gate that detects when a repo is registered on one surface but missing from another. The ceremony describes the required state; detecting violation of that state automatically is open work. Filing that gap honestly: the redundancy is only as strong as the cross-surface sync check, which does not yet exist.

Tags: `core`, `daily-logger`, `morning-cockpit`, `ci-cd`

## Roadmap pulse

**In-flight**

Core [#495](https://github.com/ojfbot/core/pull/495) [DRAFT] — ADR: correspondence-speech-act-tiers. This ADR generalises the play-well cluster's correspondence protocol to the entire fleet. The protocol defines: bead identity (each correspondence event gets a stable serial that persists across register migrations), speech-act tiers (intake, ruling, ruling-mirror, canary — each with different review and merge requirements), a derived register (the canonical state of all correspondence for a cluster, maintained as a structured YAML file), and GitHub-minted identity (the PR number and merge SHA as the authoritative timestamp). The problem it solves that per-cluster registers don't: right now, the lego-village-pipeline and play-well-library each have their own register shape and their own CI enforcement. When a third cluster onboards, the shape will drift again. The ADR codifies the shared shape and makes per-cluster registers instances of a fleet-wide primitive rather than independent inventions. A fleet without this ADR in six months has N registers with N subtly different schemas and N different lint rules — the same invisible coupling that produced the silent sweep, applied to correspondence instead of repo collection.

What is specifically still open in #495 as of Thursday evening: the speech-act tier taxonomy has a proposed shape but the ruling-mirror tier (mirroring a decision from one cluster's register into another's) has not been validated against a real case. The lego-village-pipeline tracking issue #30 mirrors this draft. The ADR has been in active authoring for less than 24 hours as of publish — it is hours-to-days from accept, blocked only on the ruling-mirror validation, not on a design disagreement.
