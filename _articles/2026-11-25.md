Tuesday's interval is a systematic false-green eradication day. Across five repos — workstation-yuri, daily-logger, core, github-actions, and BookcaseDiscovery — CI pipelines that were silently passing after real failures get the exits they should have been raising all along. The unifying pattern: a check that emits success when it ran nothing is more dangerous than a check that is simply absent. Alongside the CI hardening, ADR-0111 accepts the fleet rule that model-written claims must name their source, quote the exact words, and state where those words appear — or be marked explicitly as a hypothesis.

## The decisions

### False greens are worse than missing checks — every CI step must fail closed — *security-as-emergent-ux*

A check that exits 0 when it ran nothing provides negative assurance: it creates confident green signals that suppress human review of genuine failures. All five repos addressed this by auditing every exit path, not just the happy path. The lesson is architectural: when writing a CI step, the question is not 'does this pass on success?' but 'does this fail when something it should have checked was absent or unreadable?'

This hardening work advances the CI integrity baseline that the trust build (PH8–PH13, S40–S153) depends on — specifically the constraint that every automation step must fail closed before its outputs can be trusted. That dependency is recorded in the trust build plan in core; this interval's work is execution against it, not maintenance on the margin.

Two honest caveats on scope: the six test files in core were dark for an unknown period — the gap was discovered during this audit, not from a prior baseline. BookcaseDiscovery was running 8 of 91 test files; how long that narrowing existed is not recorded. 'Unknown period' is accurate but is itself an accountability gap. The fleet has no CI coverage baseline predating today's fixes that it can defend.

### ADR-0111: unquoted model-written claims are hypotheses, not facts — *model-behavior-as-design*

ADR-0111 (`claim-source-quote`) accepts the rule that every model-written claim about a source must name the source, quote the exact words it rests on, and state where those words are. A claim without a quote is marked as a hypothesis.

The ADR was triggered by a Nov 22 audit (tracked under core #725) that surfaced fourteen confirmed errors sharing the pattern of ungrounded synthesis written as fact. That audit is the parent issue; the ADR is the fleet rule that follows from it. The ADR is itself held to its own standard — every statement in the file names the commit and line it was read from. A link to the merged ADR file is in core PR #726; the specific line ranges are verifiable there.

This article makes one claim that ADR-0111 would scrutinize: that the fourteen errors 'all shared the pattern of ungrounded synthesis being written as fact.' That characterization derives from core #725 and the Nov 22 audit. It is not independently quoted here and should be treated as a summary, not a direct citation.

### G0 baselines fetched by exact SHA, not by branch or tag — *tooling-for-iteration*

The FleetRunner G0 contract test requires two baseline commits from repos with no default-branch presence. Rather than creating tags or branches — which would be visible signals and drift risks — `fetch-g0-baselines.sh` reads the SHAs directly from the verifier and fetches each with one retry, failing with a clear message if either commit is gone. This keeps the baseline lookup deterministic and avoids polluting the ref namespace with CI artifacts.

Tags: `ci-cd`, `hardening`

### Glob-based CI test discovery so new files run automatically — *tooling-for-iteration*

Before #727, adding a new test file to core required a matching edit to the CI configuration to wire it in — a gap that left six files dark for an unknown period. The fix uses glob patterns in each CI step so any file matching the pattern runs without a CI edit.

The tradeoff is worth stating precisely: a *misnamed* file silently joins the suite (weaker failure mode), but a file that follows the naming convention and is intentionally added will always run (stronger guarantee than the previous opt-in model). The more dangerous edge case is a file that doesn't follow the naming convention at all — it is silently excluded, not silently included. That exclusion risk is acknowledged in core #728, which documents that deliberate CI edits can still bypass the guard. #728 is a known-open follow-up, not a gap in this interval's design.

Tags: `ci-cd`, `hardening`

### BookcaseDiscovery's check-ci-tests guard: enforce the full suite structurally, not by convention — *tooling-for-iteration*

The root cause of the 8-of-91-files problem in BookcaseDiscovery was that nothing stopped a future workflow edit from narrowing the suite again. `scripts/check-ci-tests.mjs` runs before the tests and reads the actual workflow YAML, failing if the `test` script is narrowed, a step uses a file list, or the test job has an `if:` condition.

The architecturally significant detail: the guard tests itself. Bad cases are covered in `test/check-ci-tests.test.ts`, which means regression on the guard's own logic is caught in CI. This closes the gap that convention-only enforcement leaves open — the rule is executable, not advisory.

The guard does not close all bypass paths. BookcaseDiscovery #107 (opened this interval) documents one: a deliberate workflow edit that knows the guard's logic can still work around it. That bypass requires intentional action, not drift, which is why it was explicitly scoped out of this PR. The honest framing is that `check-ci-tests.mjs` raises the cost of accidental narrowing to near-zero while leaving intentional narrowing possible — a tradeoff the follow-up issue names explicitly.

This pattern — structural enforcement with self-testing, with known bypass paths documented rather than denied — is a candidate for fleet-wide adoption, but its maintenance cost (the guard itself must be maintained and can have its own bypass paths) has not been analyzed across all repos. That analysis is not in this interval.
