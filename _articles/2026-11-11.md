## The decisions

### Generation fencing as a restore safety boundary — *security-as-emergent-ux*

After a FleetRunner restore, old worker connections must be explicitly invalidated before any new work can proceed. The chosen mechanism signs a new service generation into every owner/worker request, so old-database workers fail closed rather than silently claiming or completing work against a restored queue state. From an operator's perspective, 'fail closed' means a worker presenting a stale generation is rejected at the service boundary — it does not stall silently. The observable signal is a rejection error on the worker's claim or completion attempt, not a silent disappearance. The gap in current documentation is the unset-`FLEET_GENERATION` case after a restore: if an operator omits the environment variable, the fence does not engage and no warning is issued. That operator gap is not resolved by this merge.

Tags: `fleet-runner`, `data-layer-integrity`, `nas-backup`

### Session-general path module over per-CLI hard-coded paths — *tooling-for-iteration*

Rather than duplicating session path logic across 13 CLI entry points, a single `src/eval/set-paths.ts` module holds every set's stage cache layout and the one `acceptSet` admission check. Adding a new capture session (`sf-store-001`, `sf-store-002`) requires a registry entry, not a code change in each consuming CLI. The scope boundary was deliberate: approximately 25 CLIs were left hard-coded because they were not on the critical path for the NS-K2 card. Whether any of those CLIs need session-generalization before the next F-0 GPU run on `sf-store-001` is an open owner question that this card's scope did not resolve.

Tags: `session-generalization`, `BookcaseDiscovery`

### AVFoundation passthrough for audio stripping: no re-encode, no metadata leakage — *model-behavior-as-design*

The clip ingest pipeline strips audio by routing through AVAssetReader → AVAssetWriter with the source format as the hint, copying only video and timed-metadata tracks. This preserves the original encoding exactly, verifiably eliminates audio and location tags, and avoids any quality loss or format drift that a transcoding step would introduce. The constraint is structural: the pipeline cannot accidentally re-encode because it never enters an encoding path.

Tags: `data-layer-integrity`, `BookcaseDiscovery`

### Compose predecessor PR stacks into single integration candidates before main merge — *tooling-for-iteration*

Both the core NAS service (#591) and the BookcaseDiscovery application (#92) integrated their historical draft PR stacks into single composed candidates against current main before merging. This avoids a series of incremental merges each requiring their own conflict resolution and allows independent review to validate the full composed change as a unit. The predecessor PRs are the canonical review record — they document what changed relative to each other. The composed candidate is the merge artifact. For a future maintainer reconstructing what #591 changed: read the predecessor stack (#579–#584, #586, #588, #589) as the review trail; the composed PR is the diff against main at merge time.

Tags: `fleet-runner`, `sprint`

### Nonroot AMD64 image as a NAS deployment invariant — *security-as-emergent-ux*

The FleetRunner NAS service image runs as a non-root user. This is a deployment invariant baked into the image build, not a runtime policy — a misconfigured compose file cannot accidentally grant root to the queue service. The tradeoff is a slightly more constrained build process; the benefit is that the constraint is unbypassable by operator configuration.
