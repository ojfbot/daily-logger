Thursday was a rename day at scale. The GOLF UMBRELLA landing — planned 2026-07-27, partially staged across the week — reached its final form: `gcgcca` is now `capture-agent` everywhere, `fairway` is its own repo decomposed cleanly out of `mirrorworld`, and the core defect ledger gained an independent closure loop so behavioral misreports can no longer self-resolve. PR [#5](https://github.com/ojfbot/capture-agent/pull/5) established the new identity — local directory rename, updated `l1-capture-agent` northstar registration, and the Python package migrated to the `capture_agent/` namespace. A northstar registration is a YAML record in `core/northstars/` — each repo has one. It declares the repo's role, its consumers and producers, its registered ports, and its roadmap pointer. The core validation layer reads these records on every probe sweep; a dangling reference (pointing to a repo that doesn't exist) surfaces as a defect in the ledger. This is why the sequencing of the GOLF UMBRELLA PRs was strict: fairway had to exist before mirrorworld's northstar could reference it.

PR [#7](https://github.com/ojfbot/capture-agent/pull/7) also surfaces an open question the article names honestly: the `install-agents.sh` script that *generates* the committed harness output — is it versioned? A pending ADR (draft landed in core commit `65e89a2`) addresses the convention that harness installer outputs are committed rather than gitignored, but does not yet confirm whether the generator script itself is in version control. Until that ADR is accepted and the script location is documented, regenerating the harness after a dependency update requires tracing back to the install script manually.

### Vault schema extracted to a single machine-readable file (ADR-0105) — *model-behavior-as-design*

ADR-0105 declares that the vault schema lives in exactly one place — `schema.yaml` — and prose documents cite it rather than restating field definitions.
