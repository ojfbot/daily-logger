## The decisions

### Manifest-driven domain knowledge: universal/ + apps/ layout (decomposition S3) — *tooling-for-iteration*

Core's knowledge layer was restructured so every domain-knowledge file belongs to either `universal/` (fleet-agnostic) or `apps/` (app-scoped) and is registered in a manifest, rather than living in a flat directory discovered by convention. The manifest is the canonical source of truth — it is the authoritative record of which files exist and what context they load into. The reconciler (S1) reads drift against this manifest, which means the manifest must be accurate before enforcement mode is safe to enable. That ordering — manifest first, reconciler second — is why S3 was completed in the same sprint as S1. The manifest makes which-files-load-in-which-context a machine-readable contract, not a fragile glob. Concretely: the manifest file lives at `universal/manifest.json` and `apps/<app-name>/manifest.json`; format is a flat JSON array of relative paths with optional context tags.

### Fleet reconciler ships in shadow mode first (S1) — *tooling-for-iteration*

The S1 fleet reconciler was deliberately deployed in shadow mode — it reads the manifest, walks the actual filesystem, and reports drift to stdout as a structured diff without writing anything. To read the shadow output: run `core reconcile --shadow` from the repo root; output is a JSON diff of expected vs. actual file presence. The exit condition for advancing to enforcement mode is not a time gate — it is a clean shadow run: zero unexpected absences and zero unexpected additions across the full fleet for one complete session cycle. Running shadow-first means the first real data is observational rather than mutating, so drift that exists today is measured before it is corrected, and the correction logic can be calibrated against ground truth rather than assumptions. Without a clean baseline, enforcement logic is fighting a state it never characterized. This pattern — shadow mode until clean baseline, then enforce — should be named in the ADR library as a reusable commissioning pattern.

### Dead symlinks pruned fleet-wide as a single coordinated pass — *tooling-for-iteration*

All five dead symlinks — in `workstation-yuri`, `seh-study`, `mirrorworld`, `lean-canvas`, and `frame-ui-components` — were removed in a single coordinated sweep tied to the core decomposition S2 commit that deleted `install-agents.sh` §5, the single seeder responsible for all five. Batching the removals prevents a window where some repos have broken symlinks and others don't — a partial state that is harder to reason about than either 'all present' or 'all absent'. Because the seeder is the same script across all five repos, the cause-and-confirmation documentation is the same for all five: `install-agents.sh` §5 is gone, nothing recreates the symlink, and each PR closes the gap created by S2.

### /wizard skill: stage-based human-in-the-loop setup — *assistant-centric*

The new `/wizard` skill encodes setup flows as discrete named stages with explicit checkpoints. At each checkpoint the operator sees a summary of what the previous stage completed and a prompt to confirm, redirect, or abort before the next stage runs. This is designed for operator-run, infrequent configuration flows — not end-user repeated flows. The design assumption is that the person at the keyboard is the same person who authored the flow and understands what each stage does. The checkpoints provide real assurance in that context; they would provide false assurance in a repeated end-user context where stages get clicked through without reading. Invoke with `/wizard <flow-name>`; available flows are enumerated in `core/skills/wizard/flows/`. This is a direct application of the human-in-the-loop principle from the wayfinder work: long agentic sequences need operator gates, not just a start and end.

Tags: `wayfinder`, `manifest-driven-architecture`

### Bead event-log write: fire-and-forget → await — *tooling-for-iteration*

The bead event-log write was previously fire-and-forget — meaning a session could end before the write completed, silently dropping the event. Converting it to an awaited call means the session exit cannot race ahead of the write. This matters because the bead ledger is the fleet's primary audit surface; silent drops undermine every downstream count and conformance check that reads from it. The fix is in commit `322efd9`. A `/validate` run against this fix should simulate a session-exit race: trigger a bead write near process end and confirm the event appears in the ledger before the process exits — that is the specific failure mode this change closes.
