### core ([#571](https://github.com/ojfbot/core/pull/571))

PR [#571](https://github.com/ojfbot/core/pull/571) fixes a silent side-effect in the user-scope skill installer: telemetry hooks were being registered under ~/selfco whenever skills were installed, even when no vault was configured and the operator had not requested vault setup. The new behavior requires an explicit `--telemetry-dir=/absolute/path` flag; without it, no telemetry files are created. The destination guard applies to both default and custom vault roots after symlink resolution. Importantly, the broader TypeScript suite was not run against this change — this was a deliberate scope boundary noted in the PR, not an oversight. The rationale is that the telemetry registration path is isolated from the rest of the installer; however, rollout review of existing hook migration behavior for installations that already have the old hooks registered is an open owner gate. If you have an existing installation, the current state of those legacy hooks is not automatically resolved by this PR — that migration path requires separate review. If the hook migration behavior regresses, the failure mode is silent file creation in vault paths without operator awareness, which is the exact defect this fix targets.

## The decisions

### Dedicated held-action reviewer route to avoid reopening accepted articles — *model-behavior-as-design*

When an article is accepted with suggestions still in `Needs review` state, the previous route for reviewing them required another same-date acceptance PR. PR #457 introduces a dedicated manual runner that reviews held candidates against the frozen accepted state without touching the article's status or the Actions queue. October 22 has a separate held-action record; October 24 was accepted with three held suggestions but had no separate held-action review in its four-PR article train. Article acceptance can proceed with uncertain actions held. Their admission or closure still requires independent verification.

Tags: `editorial-pipeline`, `assistant-centric`, `model-behavior-as-design`

### Derive candidate links before action-review repair, not after — *model-behavior-as-design*

A malformed action decision could receive a successful record-only repair while conflicting suggestion links stayed frozen — the repair appeared to succeed but left the record in an inconsistent state. The fix in #456 derives numeric suggestion links from candidate IDs and checks every association before isolating one record, so link conflicts use the existing full-proposal repair path rather than silently passing a partial fix. The record establishes this action-decision repair, not a shared cause of all three article delays.

Tags: `editorial-pipeline`, `ci-cd`

### Separate current evidence request from retained history in accepted articles — *tooling-for-iteration*

After article-only completion, the native pipeline retains the full history of evidence requests but drops the latest native request receipt. Previously, the display layer rendered the oldest retained request as the current blocker — a misleading diagnostic that made it appear earlier, already-resolved requests were still active. PR #462 stores a safe current receipt only after matching the full native request against its exact case, cycle, action scope, and collected source, and renders it separately from collapsed historical entries. This improves diagnostic accuracy but does not address the token budget ceiling in issue #386: a 250,399-byte discussion context against a 131,072-byte source limit is the documented failure mode, and #462 does not raise that ceiling.

Tags: `editorial-pipeline`, `ci-cd`, `hardening`

### Explicit telemetry opt-in for user-scope skill installs — *security-as-emergent-ux*

The user-scope installer in core had been registering telemetry hooks under ~/selfco whenever skills were installed — even when no vault was configured. This is a silent side-effect: files appear in the vault path without operator awareness or consent. Core #571 makes telemetry activation require an explicit --telemetry-dir flag; the destination guard applies to both default and custom vault roots after symlink resolution. The broader TypeScript suite was deliberately not run against this change (isolated path, deliberate scope boundary); migration behavior for existing hooks with the old registration is an open owner gate that this PR does not resolve automatically.

Tags: `assistant-centric`, `hardening`

### LaunchAgent one-listener cutover for Yuri Helpdesk — *tooling-for-iteration*

The Yuri Helpdesk service needed a clean cutover from its development configuration to an always-on LaunchAgent without allowing two listeners to coexist during the transition — a split-listener condition would produce unpredictable check-in routing. PR #3 documents a one-listener cutover runbook and reports that the job was active on Yuri: the landing page and API returned 200, and Helpdesk check-in #53 was saved and replayed after cutover. The article has no independent receipt for that replay, so live behavior remains a reported observation rather than independently verified delivery.
