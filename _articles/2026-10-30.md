## The decisions

### Correction precedes acceptance: no article stamps without a source-pinned review first — *model-behavior-as-design*

The October 28 train enforced the order: independent review (#490) → correction (#498) → evidence repair (#499, #501) → acceptance (#502) → outcome record (#503). This ordering is not convention — it's a hard constraint. Inverting any step would either accept incorrect prose or accept against stale evidence, both of which have caused downstream action-review failures in prior trains. The 9 confirmed errors caught in #490 included chronology inversions, a wrong commit count, and a misattributed PR — errors that would have propagated into action recommendations had acceptance preceded review. The pipeline is designed to treat model output as needing verification, not as authoritative.

### Status-index binding is distinct from action-snapshot binding — the PR #500 stop explains why — *security-as-emergent-ux*

PR #500 stopped before model entry because its evidence map referenced action-snapshot statuses, while the trusted workflow reads the full article status index. These are two different SHA-256 values covering overlapping but non-identical state. The stop was automatic: an explicit runtime guard compares the bound hash against the expected index before any model call is issued — a failed match surfaces as a workflow halt, not a silent no-op. PR #501 corrected only `articleStatusesSha256` and the derived `stateDigest`; every candidate payload, ID, and history entry was byte-identical. Conflating these two hashes would silently admit stale evidence — the workflow would proceed believing it had verified current state when it had verified a snapshot. That's the failure mode the guard prevents.

### Issue-shorthand resolution is scoped to the candidate's captured repository — *security-as-emergent-ux*

PR #499 repaired the native evidence preparation step that had rejected `issue#386` as an unqualified shorthand. The preparation layer reads candidate metadata to determine which repository the issue belongs to, then requires a fully qualified reference — `owner/repo#number` format — before binding. It rejects conflicting same-number retained references across repos and requires exactly one approved target per command. Without this scoping rule, a shared issue number across multiple repos is ambiguous, and the preparation layer correctly refuses to guess. The fix is enforced at the preparation boundary, not at the editorial layer downstream.

### Mixed-citation repair uses the existing single repair allowance for partially-visible citations only — *model-behavior-as-design*
