## What shipped

### core ([#537](https://github.com/ojfbot/core/pull/537))

PR [#537](https://github.com/ojfbot/core/pull/537) published the core-owned read contract for task and handoff inspection. The artifact is a GraphQL SDL file defining distinct source inventories and metadata, declared task/document links within one captured observation, truthful unknown repository coordinates, and queue/lease labels treated as literal evidence rather than inferred ownership. The schema is query-only — no collector, dispatch worker, or emission activation is included. That constraint is not incidental: a query-only schema lowers operational surface and eliminates a class of write-side failure modes at the cost of zero collector infrastructure. The schema lives in core; morning-cockpit vendors a byte-identical copy and generates its neutral reader types from it rather than defining its own.

## The decisions

### Core owns the inspector read contract; cockpit vendors a byte-identical copy — *assistant-centric*

The GraphQL SDL for task and handoff inspection lives in core and is consumed by morning-cockpit as a vendored, byte-identical copy — the cockpit generates its neutral reader types from that schema rather than defining its own. The alternative was letting morning-cockpit own its own schema definition; the failure mode of that path is silent type mismatch or field invention: the cockpit could define a field the core contract doesn't recognize, and that drift would surface only at query time, not at merge. The byte-comparison gate catches any divergence before merge — altering one byte in morning-cockpit's vendored SDL fails the gate loudly. The gate runs in CI on every PR against morning-cockpit that touches the vendored SDL path. File paths are not published in this article; run `/validate` below to confirm the gate holds after a clean re-checkout.

### Queue and lease labels remain literal evidence, never inferred ownership — *security-as-emergent-ux*

The inspector contract explicitly treats queue and lease labels as literal evidence from a captured observation. The inspector cannot assert that a label establishes eligibility or ownership — it can only report what was recorded. The specific failure mode this prevents: a label arriving from a stale or replayed observation being silently promoted to a live ownership claim. Whether these failure modes were observed before this contract or anticipated during design review is not recorded in the available project context; they are treated as real constraints regardless.

### Refresh is deliberate and discloses historical expiry — *model-behavior-as-design*

The inspector's refresh path is explicit rather than automatic: the cockpit triggers a refresh on demand and surfaces an expiry flag and timestamp when the fetched observation is historical or expired. This avoids the failure where a foreground inspector state is silently replaced by a stale background refresh. The `f47d4c2` commit introduced `useEvidenceInspector` and the request-lifetime controls; the final accepted hook aborts obsolete requests and checks an epoch/detail generation before adopting results. Whether this bug was observed in a running instance or caught in design review is not recorded in the available context.

### Invalid declarations and unavailable targets remain explicit, never elided — *assistant-centric*

Unresolved references, unavailable targets, and absent coordinates stay in the inspector output as explicit unknown states rather than being omitted. This is a contract-level decision: shared IDs cannot invent links or authority, and the inspector must surface what it cannot verify rather than hiding it. The accepted implementation already renders explicit diagnostic and status labels for these cases: diagnostic reason labels for invalid declarations, literal declared-link status indicators, unknown-repository text, unavailable-source reasons, and unavailable-process-identity disclosures. Any visual refinement of these renderings (badge style, label placement, annotation formatting) is optional UX work and not a prerequisite for inspector delivery. Issue [#57](https://github.com/ojfbot/morning-cockpit/issues/57) covers identity and production provenance questions, not a generic unresolved-state rendering decision.
