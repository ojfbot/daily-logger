## Roadmap pulse

All three open PRs are in daily-logger. Here is their current state and the order they should be touched.

**#309** — `fix: conditionally dispatch late daily blog runs without duplicate generation` — is the only PR in the queue with operational consequence. It closes the scheduling reliability gap exposed on October 6, when GitHub fired the scheduled run 6+ hours late and the pipeline had no guard against generating a duplicate article for a date already published. The fix adds a fallback check keyed to an external 04:00 Central cron trigger: before generating, the workflow checks whether an artifact for the current date already exists in the expected output location. If it does, generation is skipped. If it doesn't — whether the run is on-time or late — generation proceeds. The invariant a reviewer needs to confirm before merging: on a normal on-time run, the artifact check resolves to "not present" at the time generation fires, so the guard does not suppress the run. The failure mode to rule out is a race where a fast on-time run writes the artifact and a late retry also fires within the same UTC date window; the PR's guard should handle this by keying on artifact presence, not timestamp alone. There is no automated test for this in the current PR — the verification is a manual trace through the workflow YAML, checking that the artifact-existence check precedes the generation step and that the external trigger's dispatch condition cannot overlap with a standard cron run. That trace is the gate before merge. **#309 is not yet merged because it has not yet received a review pass.** It is waiting for eyes, not blocked on CI or an unresolved design question.
