## The decisions

### ADR committed for Gentle Creek + NAIP before any course data downloads — *model-behavior-as-design*

Rather than leaving the course and dataset selection implicit in commit messages, mirrorworld PR #8 committed a formal ADR capturing the operator's choice of Gentle Creek CC (Prosper, TX) and NAIP as the archival imagery dataset. The trade-offs consciously declined: Sentinel-2 (free and current, but 10m resolution is too coarse for hole-level geometry), Maxar (higher resolution but metered cost and licensing overhead inconsistent with the project's open-data posture), and Planet (tasked imagery with per-km² pricing that doesn't fit a fixed-course use case). NAIP wins on resolution (1m/px), coverage of CONUS golf courses, and public availability via USGS M2M at no per-download cost — the same archive gcgcca is querying. Writing the ADR before executing downloads means the selection rationale survives session boundaries and can be reviewed independently of the code.

### Measurement-first verdict for overlay alignment — screenshot claims withdrawn — *tooling-for-iteration*

The prior session had made a screenshot-based claim about OSM overlay registration that turned out to be wrong in the direction it was stated. PR #7 replaced visual judgment with a quantitative measurement pass: pixel-offset RMSE was computed against two known ground control points, and the residual fell within the accepted tolerance. That measurement surfaced two raster bugs that visual inspection had missed: (1) a CRS tag mismatch on the base tile — the stored metadata declared EPSG:4326 but the tile had been projected to EPSG:3857 without updating the tag, causing downstream reprojection to compound the error; (2) a resampling-filter mismatch at tile boundaries introducing sub-pixel drift visible only after the RMSE pass. Both were fixed in PR #7. The PR description formally withdrew the prior screenshot claim. The session structure rule that follows: Track A overlay decisions end with a number and a named GCP residual, not a screenshot.

### run-first, fix-what-breaks posture for USGS M2M byte-fetch — *tooling-for-iteration*

gcgcca S5 adopted an explicit operator decision to run the byte-fetch leg against the live USGS archive before the error-handling surface was fully characterised. The download executed and returned a valid NAIP tile for the Gentle Creek area — the response was a GeoTIFF bundle, authentication succeeded on the first attempt using the login-token path (the deprecated password auth migration in PR #3 was the prerequisite), and no rate-limit signal was returned. What was *not* clean: the response shape included an undocumented `orderStatus` field that the current parser ignores silently. That field and any similar envelope surprises are now the defined scope of S6. USGS M2M is free with an API key and quota-gated (not metered by byte or tile count), so the run-first posture carries no cost risk — but the quota ceiling is not yet characterized and is an S6 entrance item.
