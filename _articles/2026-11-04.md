## The decisions

### Pre-registered evaluation protocol as the merge gate for every BookcaseDiscovery card — *model-behavior-as-design*

The problem this solves is motivated reasoning in self-evaluation: if you measure first and write the threshold after, you can always find a number that passes. BookcaseDiscovery addresses this by committing every keep rule, threshold, and primary cause in its own standalone commit before any measured run executes. The protocol makes the goalposts immovable by construction.

PRs that fail their keep rule still ship — as opt-in, off-by-default, or 'basis stays off' — rather than being discarded. This matters for a system that makes identification claims: a failed arm documents the boundary of what the pipeline can do, prevents re-investigation of the same approach, and keeps the failed code available as infrastructure for future experiments that might clear a different threshold under different conditions.

One open question the article cannot answer: what prevents a future maintainer from quietly enabling a failed opt-in flag without re-running the eval? Nothing in the available evidence describes a CI enforcement mechanism for opt-in gates. If the protocol is enforced by owner discipline alone, that is a legitimate answer for a solo project — but it should be stated, not implied.

### Geometry cache as the partition contract for F-0i — *tooling-for-iteration*

At 9.3% mask-pixel overlap, adjacent book instances were sharing pixels across detection boundaries — downstream catalog lookups received ambiguous crops, and the same physical book could appear in two detection windows simultaneously. F-0i's SAM 2.1 conflict-tile and depth-seam resolution brought that to 0.05% on pilot-000.

The architectural choice is to write that result to a geometry cache rather than re-running partition on every downstream read. This keeps the expensive SAM 2.1 step idempotent: if you change the partition logic, you regenerate the cache explicitly. The cache also functions as the partition contract — it is the single source of truth for non-overlapping book boundaries that all subsequent stages consume.

What the available evidence does not specify: the cache's physical format (SQLite table, per-image JSON, or other), its precise invalidation contract, or the command a maintainer runs to regenerate it. The rationale for the design is clear; the mechanical how-to is not documented in this window's evidence.

### Negative results ship as first-class artifacts, not discards — *model-behavior-as-design*

C-7 (rarity-weighted evidence), C-6 (lookalike guard), F-0d (imprint tie-break), and F-0g2 (pooled reading) all failed their keep rules — and all merged. The pattern treats a measured 'no' as a deliverable on equal standing with a measured 'yes'.

The design logic holds in three directions. First, it documents the boundary of what the pipeline can do — which is as important as documenting what it can do. Second, it prevents rediscovery: a future maintainer who reads the record knows these approaches were tried, what threshold they missed, and by how much. Third, it keeps the failed arm's code available as opt-in infrastructure for contexts where the trade-off might be acceptable (e.g., a user who explicitly wants rarity-weighted ranking at the cost of precision).

Discarding failed experiments would leave the design space uncharted, compress the apparent capability of the pipeline, and invite the same investigation to recur — probably without the same rigor.

### Fleet-runner gate authority derived from four orthogonal axes, not role — *security-as-emergent-ux*

Core #575's gate-authority framework classifies each gate action by four axes: Impact (I0–I3: scope of effect), Reversibility (R0–R2: how hard to undo), Verifiability (V0–V3: how well the outcome can be confirmed before commit), and Trust (measured, never self-reported). Those four values map to a fixed table that derives gate authority — human-only, deterministic, or agentic — from the properties of the action itself, not from who submitted it or what repo it came from.

Trust is the axis most likely to be gamed if authority depended on identity: a system that lets an agent assert its own trustworthiness has no security boundary. By requiring Trust to be measured — observed in evidence, not claimed in metadata — the design forces the measurement rather than the assertion. The fail-closed rule follows from the same logic: if classification is ambiguous or Trust cannot be measured, the gate defaults to human-only.

What a future maintainer needs when classifying a new gate: assign I, R, V scores from their defined ranges, then find the Trust evidence (or note its absence), and read the authority from the table in #575. The table is fixed; classification is the work.
