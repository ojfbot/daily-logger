## The decisions

### Scope ACTION_REVIEW_DISABLED to the generation step, not the job — *model-behavior-as-design*

The pause variable was originally injected at the GitHub Actions job level. Because ACTION_REVIEW_DISABLED controls which config the test runner loads — production pause policy vs. fixture-based enabled/paused state — placing it at job scope caused every subsequent step, including `pnpm test`, to execute under production policy. Tests exercising accepted-article behavior failed before generation began. Scoping the variable to the 'Generate article' step alone means the unit suite retains its own explicit fixture state and is unaffected by operator-set repository variables. The alternative of a workflow dispatch input was considered but rejected: the backfill trigger is operator-initiated at the repository level, and a repo variable is the correct primitive for a pause that must survive the gap between dispatch and job start. The step-level scope is the right blast radius for this use case.

### Bounded backfill requires a temporary pause on Suggested Actions to avoid deadline consumption — *tooling-for-iteration*

The Suggested Actions candidate review makes live model calls during CI. If that review runs during a bounded backfill dispatch, it can consume the article-publication deadline before the generation step completes — the deadline is a wall-clock window, and a live model call that stalls or retries can exhaust it. ACTION_REVIEW_DISABLED prevents the review from running. The reference procedure for any future bounded backfill is: (1) set ACTION_REVIEW_DISABLED at the repository level, (2) dispatch with date_override=2026-10-30, (3) remove the variable after the job has started. No action admission or closure was claimed through the October 30 backfill run. This tradeoff is deliberate and bounded; the failure mode if the pause is omitted is deadline exhaustion before publication, not data corruption.
