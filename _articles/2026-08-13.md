## The decisions

### Instrument surface as a first-class registry enum, not a naming convention — *model-behavior-as-design*

Mock decks are registered on a dedicated `instrument` surface value that the drill client is structurally unable to reach — not just named differently or documented as reserved. Unknown surface names cause a hard startup failure. This was the critical design call: if mock isolation depended only on documentation or naming conventions, the first engineer (or future session) who registers a deck without checking the convention would silently contaminate the instrument's blind-solve validity.

For context on runtime topology: cca-prep is a CLI tool run by a single operator. "Hard failure at startup" means the process exits non-zero with a descriptive error before any drill session begins — not a server crash or a corrupted sitting record. The enforcement is lightweight but structurally correct for a solo-operator context: there is no shared registration surface where an unknown author could register a rogue deck, so the primary threat model is a future session (or a future Jim) who forgets the convention. The hard failure closes that gap without requiring ceremony.

### W3 dual sittings as a mode flag, not a new surface — *tooling-for-iteration*

The roadmap described W3 as 'dual short/full mock must ship before mock #1' — the natural reading was a new surface type. The implementation correctly identified it as a sitting-mode flag on the existing instrument surface: same deck, two traversal modes (subset vs. full 60-question parity). The smaller design is more correct because it keeps the instrument surface definition clean and avoids proliferating surface enum values for what is fundamentally a runtime parameter.

One question the article doesn't fully answer: what exactly is the subset sitting? The short mode is a deterministic subset, not a random draw — random sampling would compromise blind-solve integrity on subsequent full sittings by making overlap unpredictable. The specific subset definition (which questions, how many) lives in the PR #20 implementation and should be captured in the forthcoming three-surface ADR before M2 authorship begins.

### Stretch surface is drillable; calibration surface is not the same thing — *model-behavior-as-design*

The generation doctrine established Wednesday draws a hard line: the calibration surface holds the primary 261-item CCAR-F bank, the stretch surface holds bridge and cross-level material that is drillable, and the instrument surface holds mock decks that are neither drillable nor calibration-trackable. Three surfaces, three non-overlapping invariants. Before this distinction existed, all content lived in one pool — any new deck automatically entered the drill rotation, which would have burned mock instruments on first use.

The canonical explanation of this model currently exists only in this blog post and PR descriptions. That is a documentation gap by design admission. The `/adr` suggested action below is a blocking prerequisite for M2 authorship, not a background task — anyone registering a new deck without reading the ADR can violate an invariant the engine won't catch until startup. Until the ADR ships, treat this article as the temporary source of truth and link to it from cca-prep's README.
