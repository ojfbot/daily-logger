## The decisions

### Ledger gaps are closed as standalone PRs, not bundled with code — *tooling-for-iteration*

The silicon-empires PH1.5 ledger correction landed as its own PR (#28) with explicit documentation that it is bookkeeping-only. Mixing ledger corrections with code changes makes it impossible to audit the fleet's recorded state independently of its behavioral state — when a roadmap slice shows as 'delivered' but has no ledger entry, you cannot tell whether the work was skipped or just unrecorded without digging through commit history. The alternative — bundling the correction into the next feature PR — was rejected because it collapses two distinct audit surfaces into one diff, making both harder to read and verify.

### Techdebt entries TD-006 and TD-007 added to the core registry before work begins — *tooling-for-iteration*

Two new techdebt items — a fleet-inventory reconciler (TD-006) and movement-contract enforcement (TD-007) — were appended to core's techdebt registry on Friday, with no implementation yet. This follows the pattern established by ADR-0104 (in core, not yet public-linked): the defect ledger is written at discovery time, not at resolution time, so future sessions can find and close items without reconstructing what was known. The alternative — writing the entry only when you begin the fix — produces a changelog, not a registry. A registry written at resolution time cannot surface items that were discovered but never started. TD-007 (movement-contract enforcement) is sequenced after TD-006 because enforcing movement contracts requires a sound inventory to enforce against; it does not currently block silicon-empires PH2, but it becomes a gate before PH2 integration testing. TD-006 is the correct first item.

### f1-doctrine's README and CLAUDE.md are co-updated on every stage transition — *model-behavior-as-design*

Two separate commits updated f1-doctrine's README and CLAUDE.md to reflect S1-merged status. Keeping both files in sync on stage transitions matters because CLAUDE.md governs what the agent believes about the repo's current state at session start. If CLAUDE.md still says S0 while the registry has S1 content, the next agent session reasons from a false baseline and may re-propose work that has already landed. The alternative — updating only the README — was rejected because the README is human-facing; CLAUDE.md is agent-facing. They serve different readers and must be updated independently, not treated as duplicates.

Tags: `f1-doctrine`, `adr`, `ledger-hygiene`

### Northstar odometer is turned as a discrete commit after merge events, not inline — *tooling-for-iteration*

The northstar odometer update for f1-doctrine S1 and silicon-empires PH1.5 landed as commit `a0031cd` — a separate, named commit after the events it records. The northstar odometer is a literal append-only section in core's registry YAML: each entry names a milestone and the date it was recorded. Bundling odometer updates with merge commits makes the fleet's progress history non-atomic — you cannot grep the odometer log for a specific milestone transition without also reading through unrelated diff noise. A dedicated commit makes each entry one event, one record, one diff.
