## The decisions

### Timestamp backfill as a metadata-only, byte-preserving operation — *model-behavior-as-design*

Rather than regenerating or touching articles to add missing popover bindings, we built a deterministic replay script that adds only the three missing October merge-clock popovers while leaving every article byte, prior binding, and provenance record intact. The script (`scripts/backfill-time-month.mjs`) harvests fresh GitHub-connector PR timestamp observations and immutable local Git author/committer timestamps, freezes them into minimal projections, then replays bindings deterministically from those frozen inputs offline. Running it again produces identical output. This is the correct tradeoff because article text carries its own provenance chain: modifying it to fix metadata would corrupt the editorial history the review pipeline depends on. The backfill's coverage census documents 42 recognized occurrences, 25 admitted references, 17 supported occurrences left plain, 39 unsupported spellings, and seven unavailable source groups. However, byte preservation and documentation do not close the production gap: the source/grammar decision for approximate range intervals remains open under daily-logger #357, and the runtime resolver is not repaired by this backfill or orientation documentation.

### Diagnostic prefix boundary as a first-class test fixture constraint — *tooling-for-iteration*

The eval fixture was silently passing four healthy ADR entries that were pushing the corruption marker beyond the 1,500-character retained failure-diagnostic prefix, causing the assertions to miss their target evidence. The 1,500-character slice is used by the validator to populate a fallback `rawContext` field in failure stubs — the complete prompt is sent to the model separately, and the prefix is not scanning published article text. The eval supplies the same diagnostic prefix to assert against the stub's retained context. The alternative — raise the character limit in tests — was rejected because it would mean asserting against content the production failure stub never retains. Fixing this by reducing the fixture keeps the test honest. The remaining gap: fixture size is not currently checked at commit time, so a future prompt change could re-introduce the same silent failure.

### Agent orientation as a documented aid against timestamp coverage errors — *assistant-centric*

Core PR #539 teaches the timestamp evidence lifecycle in the daily-logger orientation before agents encounter it in practice. The failure mode being prevented is an agent mistaking a merged UI element or empty reference array for complete coverage of the latest article — a silent correctness gap that produces no error, just wrong metadata. Documentation at the orientation layer helps when loaded into an agent's context, making the constraint discoverable from the first prompt rather than only by reading the code. This complements but does not replace mechanical enforcement.
