## The decisions

### Compact generated GitHub evidence while preserving original citations (#427)

The token budget correctly stopped the earlier request once the output reserve was included. The repair changes what the model sees rather than increasing that budget. Generated transport metadata has a compact view; raw sources, authored content, and original citation lines remain available. Hidden metadata cannot be cited as if the model had inspected it.

The same change preserves lossless source receipts and the first-review, archive, and second-review sequence within the existing 64 KiB dated-file limit. These offline controls establish bounded serialization and citation behavior. They do not establish a live post-compaction token count, successful verifier fit, or the quality of an action decision. A small synthetic compiler probe cannot supply that missing full-evidence measurement.

### Repair an unsupported union without treating it as compiler qualification (#426)

The strict action-review tool schema contained two unsupported `oneOf` nodes. The repair converts only object branches that share a required discriminator with distinct string constants. Ambiguous shapes throw at the conversion boundary, and the original Zod validators remain in place.

Regression checks exercise the actual proposer and verifier request builders. Those checks prove the local transformation, not provider acceptance. The later probe result matters because it shows that the combined strict response form still fails compilation after a simpler form was prepared. Another unchanged request would not test a newly repaired condition.

Tags: `editorial-pipeline`, `model-behavior-as-design`

### Recover a failed editorial request without replaying it (#425)

A claimed continuation could fail before producing review output and remain locked. Owner recovery records an explicit resolution on the existing PR, bound to the failed attempt and its correspondence. It preserves that attempt and permits a distinct fresh request only through the existing policy, source, quota, claim, and output-proof checks.

The implementation uses structured `resolve_editorial_request` and `request_clean_acceptance` correspondence through the editorial continuation service. The source does not provide the draft's proposed `/editorial-resume` slash command. [#424](https://github.com/ojfbot/daily-logger/pull/424) also says it adds no new UI trigger button. Resolving a failure does not itself run a model, accept the article, or authorize another paid request.

Tags: `editorial-pipeline`, `security-as-emergent-ux`, `assistant-centric`

### Use bounded synthetic probes to distinguish compiler failures from article fit (#428, #429, #430)

The manual probe uses guarded GitHub `workflow_dispatch` inputs, fixed public synthetic requests, and explicitly approved execution limits. It does not load an article or settle actions. There is no supported `/action-review-probe` slash command in these changes.

The safe artifact distinguishes provider HTTP observations from workflow and transport failures. A successful HTTP response and valid synthetic output are separate observations. A failed job may instead reflect preparation, authorization, transport, output validation, or artifact retention. Only a validated provider error receipt supports the conclusion that the provider rejected the schema.

The consumed [#430 probe](https://github.com/ojfbot/daily-logger/pull/430#issuecomment-6359598495) produced that evidence: HTTP 400 classified as `invalid_request_error` and `schema_complexity`. It did not produce a verifier result or authorize another dispatch. Compiler acceptance, useful nonempty review output, and full-article evidence fit remain different checks.
