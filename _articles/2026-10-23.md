## The decisions

### Compact generated GitHub action evidence into model-only views before review (#427) — *model-behavior-as-design*

The October 21 hosted action-review request reached 193,064 input tokens. The fixed 12,000-token output reserve pushed it past the 200,000-token budget ceiling and correctly aborted. Rather than raising the budget ceiling — which would make future overruns harder to predict and harder to price — the fix builds a model-only view of generated GitHub transport metadata while keeping raw sources, authored bodies, diffs, and original line numbers intact. The compacted view keeps the first-review → archive → second-review sequence inside the existing 64 KiB dated-file limit. The token count after compaction is not yet published in this record; that measurement belongs in the #416 run result. What the decision reveals about the pipeline's shape: evidence grows with article count, and the compaction target will need to be revisited as the archive deepens. The fix is a point solution; the growth rate of evidence as articles accumulate is an open characterization question.

### Convert unsupported oneOf discriminators to anyOf in the strict action-review tool schema (#426) — *model-behavior-as-design*

Anthropic's API rejected the strict action-review tool schema because it contained two `oneOf` nodes — the provider's strict-tool path requires `anyOf` for discriminated unions. The fix converts only object branches with a shared required discriminator and distinct string constants to the supported form; ambiguous union shapes are rejected at the conversion boundary, not silently accepted. When an ambiguous union shape is encountered, the conversion throws explicitly rather than silently degrading — the failure mode is a thrown error, not a logged warning or silent pass. The regression test exercises the actual proposer and verifier requests and fails on the unadopted base, making the repair verifiable without a live provider call. Original Zod validators are retained.

### Add explicit owner recovery for failed editorial requests (#425) — *security-as-emergent-ux*

A claimed editorial continuation that fails before producing review output was previously locked against replay — no safe resolution path existed short of abandoning the PR. The fix adds an explicit owner resolution on the existing PR, binding the immutable failed attempt and complete canonical correspondence without starting new model work. Mechanically, recovery is triggered by running the owner-resolution command against the failed PR's claim record; it sets a resolution state field that unlocks the fresh-review path. Resolution leaves the next review as a distinct request with its existing policy, source, quota, claim, and output-proof gates intact. The specific invocation surface is a slash command detailed in the suggested actions below.

### Introduce a manual synthetic probe workflow for strict action-review schemas (#428, #429, #430) — *tooling-for-iteration*

Three sequential PRs built and hardened a manual diagnostic workflow that tests fixed public synthetic requests for the two review models without loading an article, changing actions, or starting an editorial request. This isolates the provider's schema-acceptance question from article-fit and factual-review questions — a separation that was missing when the October 21 failure first surfaced and made the failure mode opaque. To use the probe: run the designated slash command with a synthetic request payload; bounded status, hash, and usage fields are accepted; arbitrary error text and non-allowlisted error types are discarded at the transport boundary. A pass result means the schema is accepted by the provider. A fail result means the provider rejected the schema before any article content was evaluated. The probe does not cover full-article fit or factual review — those remain separate unqualified gates, as the critical path note reflects.
