## The decisions

### Revoke Codex subscription qualification after live tool exposure — *security-as-emergent-ux*

The synthetic API-auth probe used to build the earlier Codex qualification never sent an authenticated request against a live ChatGPT subscription — it omitted tool fields that are only visible in real subscription rollouts. When live rollouts exposed those additional tools, the qualification assumption was invalidated. The correct response was not a narrower patch: a patch would re-establish a qualification whose probe still doesn't match live behavior. Core 0.3.4 empties the typed Codex qualification allowlist entirely. Both former tuples return native-profile-unqualified before a provider probe or supervised dispatcher is created, with no Claude fallback. The redesigned probe — the only path back to any Codex entry in the allowlist — must account for tool fields as they appear in real subscription rollouts, not synthetic API-auth responses. No PR is currently open for that probe redesign and no owner has been assigned. The empty allowlist is the correct state until that probe exists and passes.

Tags: `native-dispatch`, `security-as-emergent-ux`, `hardening`

### Accept only exact observed macOS preference-absence messages in supervised preflight — *security-as-emergent-ux*

macOS `defaults` reports absent preferences with version-dependent wording; the preflight was rejecting both pinned providers on Yojimbo because the newer message variant wasn't recognised. The fix accepts only the two observed old and new messages for the queried domain and key. Unexpected diagnostics, mismatched queries, present settings, and process failures all remain held. The specific accepted strings are pinned in the fix — anyone debugging a preflight hold on a future macOS version should check that file first; a new message variant from a future OS update would cause a hold, which is the intended safe default.

Tags: `native-dispatch`, `hardening`

### Incremental versioned release series for native-dispatch (0.1.0 → 0.3.4) — *tooling-for-iteration*

Five PRs across this window each shipped a discrete, numbered @core/native-dispatch version rather than accumulating changes on a branch. Each version has a fixed passing-test count (40, 1,763, 1,799, 1,803) and an independent confirmation step. This creates a reviewable progression where any regression is immediately locatable without bisecting an accumulated diff — the version number is the bisect unit.

### 4K ingest held to no-code-change invariant by design-time resolution independence — *model-behavior-as-design*

BookcaseDiscovery's ingest pipeline was written to be resolution-agnostic: `nativeSize` reads stored portrait orientation (rotation 0, identical across 1080p and 4K clips), sharpness scoring operates on a 640 px grey copy regardless of source resolution, and memory buffers were sized to tolerate the scale increase. The 4K intake PR required zero code changes. This is validated at ingest and test-suite level (1,905 passing, 13 skipped). It is not yet validated at model-inference level — no model has run against the 4K tier. GPU measurement against sf-store-003 clips is the next card; sf-store-005 remains held out pending owner ruling OC35.
