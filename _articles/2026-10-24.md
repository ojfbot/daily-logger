## The decisions

### Pair each suggestion with its own disposition before the verifier runs — *model-behavior-as-design*

PR #440 pairs each original suggestion with its own proposed disposition so the verifier evaluates the correct candidate. That prevents reasoning about one candidate from being substituted for another. It does not introduce partial admission. Native application still requires exactly one disposition and independent verdict for every awaiting candidate, and an unresolved required candidate can hold the complete round. Proposed changes are applied to a clone and returned only after the whole review passes.

Tags: `editorial-pipeline`, `assistant-centric`

### Run editorial child processes asynchronously so the parent stays responsive — *security-as-emergent-ux*

PR #440 moves long subprocesses to an asynchronous runner so the parent can process connection closures while a child runs. Its local socket regression supports that responsiveness change. The historical hosted EPIPE cause remains unproved; the evidence does not identify a GitHub webhook channel as the cause. The runner preserves stdin EOF, the combined 1 MiB raw-output limit, stderr diagnostics, and ordinary child errors. Receipt delivery still uses one GitHub API POST without automatic retry. Pairing and transport responsiveness share a PR, but neither establishes that the next hosted review or receipt delivery will succeed.

Tags: `ci-cd`, `hardening`

### Resolve captured suggestion IDs before the independent verifier reads the proposal — *model-behavior-as-design*

PR #438 repairs failures caused by a proposer copying a captured suggestion with changed fields. The proposer selects the captured candidate by ID. Code then derives its unchanged command, repository, and description before the independent verifier reads the canonical proposal. Invalid references, cross-linked indices, and identity overrides stop before verification. New or amended work stays explicit; the model cannot silently replace the original capture.

Tags: `editorial-pipeline`, `security-as-emergent-ux`

### Admit captured invocations with arguments as ordinary queue entries — *security-as-emergent-ux*

Suggestions like `/owner-gate core#561` carry arguments that previously caused queue admission to fail before the verifier ran, blocking October 21's review entirely. PR #439 admits the exact invocation — with arguments intact — only when it matches an immutable capture and passes native evidence checks. Arguments and admission proof survive save/reload, retries, and later action updates. This grants no execution or owner-decision authority; it only allows the queue to hold the full invocation form that the capture records.

Tags: `editorial-pipeline`, `assistant-centric`

### Repair malformed action output within its originating role, not by restarting the pipeline — *model-behavior-as-design*

PR #441 retries the role that returned malformed output. A verifier repair keeps the exact validated proposal and evidence rather than restarting the proposer. Both roles share one malformed-output repair budget. The correction prompt uses a bounded, closed vocabulary of role, phase, path, error code, type, and required-field facts. It excludes raw replies, arbitrary field names, provider-authored text, raw validation messages, and a schema diff. Native validation still checks the repaired response; a successful local regression does not guarantee that a live model will return a valid or useful review.

Tags: `hardening`, `editorial-pipeline`
