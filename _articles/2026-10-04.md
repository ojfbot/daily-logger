PR [#495](https://github.com/ojfbot/core/pull/495) published the bounded correspondence pilot contract as a Proposed document. Background: the correspondence program defines how the system makes claims, references evidence, and distinguishes between two categories — authored claims (things the system or a human asserts directly, owned by the author) and evidence-derived assessments (things inferred or synthesised from observed data, not attributable to a single author). The boundary matters because mixing the two silently is how an AI assistant produces confident-sounding outputs that aren't actually traceable to evidence. The pilot contract narrows the original fleet-wide scope to the core pilot only: work/revision references, the authored-claim vs. evidence-derived distinction in practice, and the rules for trustworthy human-agent correspondence. Marking it Proposed, not Accepted, is intentional — 'Marking it Accepted on day one would imply the design has been validated by real-world usage, which it hasn't.' The pilot must run and generate evidence before the design is ratified. The Proposed status also signals that the boundary conditions are available for targeted critique before they lock. The constraint most likely to need revision after the pilot: the authored-claim boundary in edge cases where the system synthesises from multiple human-authored sources — it is not yet clear whether that output counts as authored or derived.

## The decisions

### Schedule the blog workflow in America/Chicago, not UTC — *tooling-for-iteration*

The Daily Dev Blog cron was anchored in UTC, which causes the run time to drift one hour at each DST boundary — articles generated at 09:00 UTC in winter arrive at 03:00 local, but 04:00 local in summer. The drift had already occurred at least once. Pinning the schedule to America/Chicago via GitHub Actions' native timezone field keeps the 3:30 AM local target stable year-round. The alternative — manually adjusting the UTC offset at each DST boundary — is error-prone and produces no audit trail. No meaningful cost: GitHub Actions resolves named timezones natively.

Tags: `ci-cd`, `editorial-pipeline`

### Daily Cleaner is now sequenced after a successful Daily Dev Blog via Actions needs: dependency — *tooling-for-iteration*

Previously the Daily Cleaner ran on its own independent schedule. If the blog bot failed mid-run — leaving a partial context state — the cleaner could remove stale-looking artifacts that the next generation attempt still needed, silently destroying recovery context. The fix uses a GitHub Actions `needs:` dependency: the Daily Cleaner workflow triggers only when the Daily Dev Blog job completes successfully. This eliminates the race condition and makes the ordering deterministic. The mechanism matters for debugging: if the cleaner fires when it shouldn't, the `needs:` condition in the workflow definition is where to look. The cost is a slightly longer total CI window; the benefit is that the cleaner only ever sees a post-success state.

Tags: `ci-cd`, `editorial-pipeline`

### Bounded correspondence published as Proposed, not Accepted — *model-behavior-as-design*

Core #495 documents the pilot contract — authored-claim vs. evidence-derived assessment distinctions, work/revision reference rules, human-agent correspondence boundaries — as Proposed rather than Accepted. This is a deliberate epistemic signal: the design has not been validated by real-world pilot usage, and shipping it as Accepted would misrepresent that. Proposed status keeps the boundary conditions open to targeted critique before they lock. What would a failed pilot look like? The most likely failure mode is the authored-claim boundary breaking down in synthesis cases — where the system aggregates across multiple human-authored sources and the output is neither cleanly authored nor cleanly derived. That edge case is the one to watch during the pilot run. What evidence is required to flip status to Accepted is not yet formally specified in the document; that done-when criterion needs to be written before the pilot begins.
