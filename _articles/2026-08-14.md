## The decisions

### Instrument surface as a hard wall, not a soft filter — *model-behavior-as-design*

Mock decks carry `surface: "instrument"` — a runtime JSON field read at access time, not a build-time exclusion. The intended enforcement pattern is a single check at every drill-bank access point before any question is processed; the three bugs fixed Thursday all shared one root cause: code paths that accessed deck items without first reading the `surface` field. The wall is not enforced by a single middleware gate — every access point is responsible for checking independently, which is why three separate paths were found violating it. The fix was to add the surface check to each violating path, not to relax the wall. What breaks without the wall: instrument questions appear in the drill pool before the sitting, destroying the unseen-item guarantee that makes a mock score meaningful. That's a candidate-integrity failure, not just a stat inflation issue.

Tags: `generation-over-content`, `instrument-surface`

### One sitting must produce exactly one telemetry row — *security-as-emergent-ux*

A race condition in the mock runner was writing two rows within three seconds for a single sitting. The fix enforced a sitting-scoped deduplication check at write time. The failure mode matters: double rows inflate domain-score averages and corrupt the readiness signal the operator uses to decide when to sit the real exam. This is a data-integrity bug reframed correctly as a trust failure — the telemetry's only job is to tell the operator when readiness is real, and a duplicated row breaks that signal silently.

Tags: `cca-prep`, `ci-cd`

### CCDV-F activated as a second independent exam track — *assistant-centric*

Rather than extending the CCAR-F deck registry with cross-exam material, CCDV-F gets its own `decks/ccdv-f/` directory and exam stub. Blueprint-quota enforcement, telemetry, and deck generation are completely independent between exams. Mixing them would make coverage metrics ambiguous — a CCAR-F domain percentage would bleed CCDV-F item counts. The two tracks now run, score, and report independently.

Tags: `generation-over-content`, `cca-prep`

### Lab home ruled to `cca-prep/labs/` — no external path dependencies — *tooling-for-iteration*

Wayfinder ruling 455 confirmed that workbench labs live at `cca-prep/labs/` inside the fleet repo, not at an external path like `~/ojfbot/newline-ai-course/labs/cca/` which was never a fleet repo and does not exist under version control. A ruling commits the decision to core but does not automatically rewrite consuming repos — which is why PR #26 is still open: `plan.html` carries a hardcoded reference to that phantom path. The correction is one line. Merge before any Lab 1 template work begins or the phantom path re-enters scope.
