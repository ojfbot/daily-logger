## The decisions

### f1-doctrine is a question layer — it never computes or emits numbers — *assistant-centric*

The repo's single hard constraint: it holds doctrine (which strategist questions to ask, bound to f1-substrate call identifiers) but never executes those calls or returns telemetry values. A QuestionNode carries a substrate_call binding field — the name of the call to make — not a result field. This keeps the knowledge layer decoupled from the data layer and prevents a specific failure mode: doctrine nodes that embed computed values become stale on data refresh and surface as confident wrong suggestions. The enforcement mechanism is an import boundary — no f1-substrate import is permitted in the doctrine package. The ADR formalizing this constraint is not yet committed (see suggested actions); it currently exists only in CONTEXT.md prose. That ADR is a prerequisite for merging S1, not a follow-on.

### S0 ships skeleton and constraint model before any retriever code — *model-behavior-as-design*

The bootstrap sequence deliberately front-loads the decision record — three staged ADRs, taxonomy v1, northstar — before a single line of retrieval logic. This is the lesson from f1-pit-wall: building the eval corpus after the retriever produces a corpus shaped by retriever assumptions. Writing doctrine first forces the question vocabulary to be independent of how it will be retrieved. The taxonomy v1 defines three classification axes (race_progress, stint_position, decision_altitude) and four personas. S1 immediately stress-tested those axes and found real signal: one axis flat, one untested, one persona seed-empty. That is what front-loading the taxonomy buys — you discover structural gaps before the retriever has had a chance to paper over them.

### race_engineer persona seeded empty — fabrication explicitly rejected — *model-behavior-as-design*

The S1 migration (f1-doctrine PR #1, open) discovered that the race_engineer persona has zero seed nodes. Rather than inventing doctrine to fill the gap, S1 left it empty and pinned a test asserting the empty state: test_race_engineer_is_first_class_but_seed_empty. This is a correctness-over-completeness call: a wrong doctrine node is worse than a missing one because it will surface as a confident wrong suggestion. The named test makes the empty state findable and auditable — a future engineer who sees it knows it is intentional, not a bug. The graduation criterion for a persona moving from empty to seeded is: at least one Tier B citation (published strategist text or race-team document) bound to a QuestionNode with a real substrate_call. That standard is implicit in the tier model; it should be made explicit in the compute-boundary ADR.
