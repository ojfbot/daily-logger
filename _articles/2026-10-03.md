## The decisions

### Fleet census walks live repo list, not a frozen hand-record — *tooling-for-iteration*

morning-cockpit's `/api/fleet-structure` adapter previously read from a hand-kept list frozen at the 2026-07-25 walk. PR #53 replaced it with a live `gh repo list` call on each request — repos born after that date are now automatically included without a manual update. The tradeoff is a synchronous network call with no caching layer: if the GitHub API is rate-limited or the `gh` credential rotates, the endpoint returns an error rather than a stale-but-available response. That failure mode is accepted for now; the rationale is that a hard error is more visible than silent drift, and the fleet census is a low-QPS internal endpoint. Graceful degradation (serving a cached snapshot on API failure) is the obvious next hardening step and is not yet scoped.

### Selfco inbox advisory stays non-blocking in the vault lint gate — *security-as-emergent-ux*

Core #499 refined the vault lint gate: unfiled captures under `raw/inbox/` are surfaced as an advisory filing queue but do not block gated ingest, note, or cultivate commits. Unfiled raw material elsewhere still blocks. This is a deliberate asymmetry — the inbox is a legitimate temporary landing zone, and treating it as a hard gate would interrupt normal vault operation every time a capture hadn't been filed yet. The gate is not symmetric by accident; it's symmetric by default and asymmetric by design for the inbox path specifically.

### Codex heartbeat registered as a provisional fleet-runner census entry — *assistant-centric*

Core #502 registers the Selfco vault hygiene Codex heartbeat as the first entry in the fleet-runner census (issue #307) under a provisional flag. The fleet-runner census is a JSON manifest mapping autonomous agents to their coordination metadata; a provisional entry is fully formed but marked not-yet-runtime-integrated. Codex remains its own scheduler and executor — the registration makes the heartbeat's existence visible to fleet-runner consumers before the full runtime integration is built. This preserves the separation between fleet-runner (coordination layer) and Codex (autonomous executor) while creating a real artifact for consumers to reference.

### Daily-logger generation gated on meaningful change signals — *tooling-for-iteration*

PR #289 changed the generator to fire only when the 09:00 UTC window contains a qualifying commit, PR change, or issue lifecycle event, and to exclude commits authored by the logger's own bot account. The original trigger predicate matched on any commit activity in the window — including the article commit the logger itself had just pushed. That made every successful generation a qualifying event for the next run: a potential self-sustaining loop. The fix was caught in review before it fired in production. The author-identity exclusion is the guard; the risk is that a future commit message or author pattern could accidentally match again. The qualifying predicate is now logged per item, making the trigger auditable and future regressions detectable before they compound.
