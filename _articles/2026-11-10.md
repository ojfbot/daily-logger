## The decisions

### Content-addressed storage chosen for the NAS backup target — not a file mirror — *tooling-for-iteration*

BookcaseDiscovery PR #89 (DL-6) uses a content-addressed store on the NAS target rather than a plain rsync mirror: each file is stored by its hash, unchanged files are not re-copied, and deleted files are retained in older snapshots until pruned by --keep N. This makes every backup run append-only by default, which matters for recovery: you can never overwrite a good backup by running a bad one.

Tags: `data-layer-integrity`, `nas-backup`

### SQLite VACUUM INTO chosen for consistent ledger snapshots under live writes — *tooling-for-iteration*

The backup snapshot step copies SQLite fact ledgers using VACUUM INTO from a read-only connection rather than a raw file copy. A raw file copy of an open SQLite database can capture an inconsistent mid-write page — VACUUM INTO reads the last committed state atomically, which matters because the event ledger may have an open writer during a backup run. The tradeoff is that VACUUM INTO is slower for large databases, but correctness of the fact ledger is non-negotiable in a system where the ledger is the authoritative truth source.
