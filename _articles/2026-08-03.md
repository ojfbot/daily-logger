## The decisions

### selfco-box transport split: remove Claude from the ingest hot path — *assistant-centric*

The transport daemon now lands raw captures to raw/inbox/ without invoking Claude at all. LLM processing happens downstream in a separate, explicitly scheduled step — a launchd-triggered agent run that watches raw/inbox/ for new items. This separation eliminates a class of failure where a transient API error at capture time permanently loses an ingest event, because the capture and the processing are now decoupled at the filesystem boundary. It also eliminates a cost: every Claude API call removed from the ingest path is a line item not incurred. The number of calls eliminated per day is not yet instrumented — that is a known gap and a candidate first S33-adjacent metric to establish.

Tags: `selfco-box`, `assistant-centric`, `model-behavior-as-design`

### Poll-mode deployment alongside webhook transport — *tooling-for-iteration*

Environments where the inbound webhook isn't reachable (selfco-box runs on developer hardware behind NAT, no public IP) get a launchd plist + poll script that checks raw/inbox/ on a schedule and applies a mirror-lag check before forwarding. Two transports coexist without a protocol negotiation step — the deployment environment determines which activates. Neither transport requires the other to be present. This is the correct design for a single-operator fleet where network topology is not uniform.

Tags: `selfco-box`, `build`

### UNVERIFIABLE as a first-class bead-ledger state — *model-behavior-as-design*

Before this change, bead-lint treated an event loop with no registered verifier as ambiguous-open: it passed silently and was not counted as either closed or broken. That made absent verification indistinguishable from a passing case — a gap that looked like a green light. The S32 liveness test now classifies these loops as UNVERIFIABLE. An unverifiable loop is a known gap, not an oversight — naming it explicitly prevents bead-lint from treating absent verification as a passing case. The value of this state is that it is countable: you can now ask 'how many loops are unverifiable' and get a real number, which is the prerequisite for any future verification coverage metric.

Tags: `core`, `bead-ledger`, `model-behavior-as-design`

### Age as the pickup queue's organizing principle in morning-cockpit — *tooling-for-iteration*

morning-cockpit's bead-lane finalizeItems now stale-marks by arrival age first. Before this change, a high-activity repo could continuously push fresh beads to the top of the queue, starving older work indefinitely. Age-ordering is a fairness guarantee: no bead older than N minutes can be preempted by a newer arrival. N is configurable in the finalizeItems call signature. The default value is not documented in this article — that is a gap that should be resolved before the next morning-cockpit session, because 'age-ordering is active' and 'the threshold is correct' are two different claims.
