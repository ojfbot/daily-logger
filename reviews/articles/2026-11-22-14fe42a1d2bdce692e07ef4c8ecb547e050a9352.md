### C11 — The two-build check proves repeatability, not a clean build machine

- **Article location and quote:** [line 87](https://github.com/ojfbot/daily-logger/blob/14fe42a1d2bdce692e07ef4c8ecb547e050a9352/_articles/2026-11-22.md#L87) frames the double build as protection against "a compromised build environment". It says the check "converts a trust assumption into a falsifiable check", so that a consumer verifies "a property the builder already proved".
- **Primary evidence:**
  - The [FleetRunner release workflow](https://github.com/ojfbot/core/blob/main/.github/workflows/fleet-runner-release.yml) runs both builds in one `release-image` job on one `ubuntu-24.04` runner, through [`release-image.sh`](https://github.com/ojfbot/core/blob/main/packages/fleet-runner/scripts/release-image.sh).
  - Each build gets a fresh BuildKit builder. A difference between the two passes is caught, but a compromised runner that alters both builds the same way is not.
  - [Core #648](https://github.com/ojfbot/core/pull/648) claims reproducibility, not tamper detection.
- **Correction:** say the check proves the build is repeatable from the same commit, catching stray inputs and anything that varies between passes. Say it does not show the runner itself is clean; that would need an independent rebuild elsewhere.
- **Disposition:** open
