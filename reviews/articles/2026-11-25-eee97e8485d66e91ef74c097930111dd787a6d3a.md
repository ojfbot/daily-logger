### C9 — The held Bookcase command can hide a failing test run and repeats completed validation

- **Article location and quote:** the fourth held candidate at [line 146](https://github.com/ojfbot/daily-logger/blob/eee97e8485d66e91ef74c097930111dd787a6d3a/_articles/2026-11-25.md#L146) proposes `node scripts/check-ci-tests.mjs && pnpm test 2>&1 | head -40`, saying the output should list all 91 files and exit 0, while narrowing should exit 1.
- **Primary evidence:** [BookcaseDiscovery #106](https://github.com/ojfbot/BookcaseDiscovery/pull/106) already records the guard and full-suite run, with 92 files rather than 91. The [GNU Bash pipeline contract](https://www.gnu.org/software/bash/manual/html_node/Pipelines.html) says a pipeline returns the last command's status unless `pipefail` is enabled; this command can therefore return `head`'s success after `pnpm test` fails. With `pipefail`, early truncation can instead surface the upstream SIGPIPE.
- **Correction:** treat #106's completed run as the existing receipt. If a fresh supervised rerun is actually needed, run `pnpm check:ci-tests && pnpm test` without the truncating pipeline, or capture output separately while preserving the test command's status. Expect 92 collected files at the recorded revision.
- **Disposition:** open
