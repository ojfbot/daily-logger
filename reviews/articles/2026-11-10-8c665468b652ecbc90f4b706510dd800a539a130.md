## Confirmed errors

### C1 — The backup does not store every file

- **Article location and quote:** line 25 says “each file is stored by its hash.”
- **Primary evidence:** [BookcaseDiscovery #89](https://github.com/ojfbot/BookcaseDiscovery/pull/89) and its pinned [backup contract](https://github.com/ojfbot/BookcaseDiscovery/blob/c4659cb037633cdf501076d0a29361f277524aa4/docs/backup.md#L24-L33) exclude the credentials file, restore-drill scratch roots, and specified SQLite WAL, SHM, and journal files.
- **Correction:** say regular data-root content is stored by hash subject to the documented credential, scratch-root, and SQLite side-file exclusions.
- **Disposition:** open

### C2 — Default pruning and the quick-check blind spot defeat the absolute recovery guarantee

- **Article location and quote:** line 25 says “every backup run [is] append-only by default” and “you can never overwrite a good backup by running a bad one.”
- **Primary evidence:** [BookcaseDiscovery #89](https://github.com/ojfbot/BookcaseDiscovery/pull/89) says the default `--keep 4` run prunes older snapshots and bodies no retained manifest names. The pinned [limitations](https://github.com/ojfbot/BookcaseDiscovery/blob/c4659cb037633cdf501076d0a29361f277524aa4/docs/backup.md#L133-L142) also say a same-size, same-mtime source change is not reread and can go unseen.
- **Correction:** say object bodies and kept manifests are not overwritten, while default retention deletes aged snapshots and unreferenced bodies and the size/mtime quick check has a documented silent-corruption blind spot. Do not promise that repeated bad runs can never age out the last good snapshot.
- **Disposition:** open
