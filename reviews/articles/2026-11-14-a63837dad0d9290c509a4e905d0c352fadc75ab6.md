### C2 — The loopback fix governs an outbound worker endpoint, not an exposed worker listener

- **Article location and quote:** lines 24 and 44 say unrestricted HTTP left “the worker's HTTP surface reachable” from the local subnet and frame loopback binding as an inbound compensating control.
- **Primary evidence:** [#601's final worker settings parser](https://github.com/ojfbot/core/blob/d51afde050f7b6cc09653c6a31e9367a22f0d973/packages/fleet-runner/src/worker-settings.ts) parses the configured `endpoint` URL used by the worker client. It allows `http:` only when the endpoint hostname is `127.0.0.1`, `::1`, or `localhost`; all remote endpoints require HTTPS. The [install contract](https://github.com/ojfbot/core/blob/d51afde050f7b6cc09653c6a31e9367a22f0d973/packages/fleet-runner/worker-release.md) describes the same outbound endpoint rule and does not add a worker HTTP listener.
- **Correction:** describe the defect as permitting an insecure remote HTTP endpoint for worker traffic. Do not claim that #601 exposed a worker-owned HTTP listener to subnet callers or that a Unix socket would directly replace the corrected surface without a separate design decision.
- **Disposition:** open
